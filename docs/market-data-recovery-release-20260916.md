구현 식별자: `feed-recovery-20260916`. 주문 전략 버전은 `kr-etf-range-v0.2`로 유지해 기존 주문 원장과 검증 상태를 보존한다.

## 실제 원장 조사

9월 16일 원장에서 75,386ms 시세 공백과 WebSocket 연결 실패 기록을 확인했다. 이후 메모리 표본 초기화의 모든 원인은 기존 로그만으로 확정할 수 없다. REST HTTP 500을 시세 단절 원인으로 단정하지 않는다.

확인 시점까지 A 전략의 완료 구간 8개 중 7개는 미체결, 1개는 3주 왕복 체결이었다. 매수·매도 금액 각각 40,245원(주당 13,415원), 매도 종료 사유 stop_loss, 설정 수수료 합계 약 11.79원이다. 새 구현의 성과로 합산하지 않는다.

## 변경

- 연결 종료와 10초 초과 공백 때 기존 동일 거래일 30분 표본을 보존한다. 현재 시세는 무효화해 새 실시간 수신 없이 주문하지 않는다.
- 재시작 시 SQLite에서 시간·가격·거래일을 검증하고 초별 중복을 제거해 복원한다. 기존 quotes 구조는 보존하고 새 공급자 시각은 별도 quote_source_times 테이블에 기록한다. 기존 자료의 수신 시각을 공급자 시각으로 가장하지 않는다.
- 데이터 품질 함수를 주문 신호·자동 사전검증에 적용한다. 최근 30분/5분 표본 수, 커버리지, 공백, 조건부 공백 해소 시각을 보고한다.
- WebSocket 제어를 REST 대조 루프에서 분리했다. 연결 세대로 늦은 종료 콜백을 무시하며, 이전 소켓 종료 확인 전 새 연결을 만들지 않는다. 종료 확인이 오지 않으면 겹쳐 연결하지 않고 대기한다.
- 1·2·5·10·30초와 작은 무작위 지연으로 재접속한다. 구독 승인과 호가·체결 신선도를 확인한다. 승인키는 메모리에 최대 1시간 보관하며 구독 거절 시 폐기한다.
- 공급자 공식 유량 안내에서 모의 REST 초당 1건, WebSocket 계좌당 1세션, 접속키 발급 초당 1건을 확인했다. 기존 REST 직렬 호출 간격은 유지한다.

- A/B 가상 비교의 단절 당시 진행 중 시나리오는 불확실 사례로 보존하고 제외한다. 관측하지 못한 경로를 가상 체결로 계산하지 않는다. 모의계좌 실제 체결 원장은 변경하지 않는다.

## 검증과 제한

71개 테스트 및 TypeScript·ESLint·서버 번들 빌드 통과. 10초 경계, 긴 공백, 낮은 커버리지, 동일 일자 복원, 새 시세 없는 진입 금지, REST 오류의 표본 보존, 연결 중복·늦은 콜백·구독 확인을 테스트했다. 기존 주문·취소·부분체결 테스트도 통과했다.

관찰 모드로 EC2에서 원장 복원 1,766개, 두 구독 OPSP0000, 최신 호가·체결 수신, 계좌 대조를 확인했다. 해당 관찰 구간은 주문 비활성 상태였다. 배포 정지 때문에 발생한 25,655ms 공백을 data_gap_30m으로 표시하는 것을 확인했다.

실제 긴 공백을 메울 수 있는 동등한 과거 호가 자료는 확보하지 않았으며, REST 분봉이나 가격 복제로 보충하지 않는다. 따라서 실제 10초 초과 공백이 창 안에 있으면 대기한다. 이 변경은 매매 빈도나 수익 증가를 보장하지 않는다. 장중 반복 장애에 대한 장기간 검증은 후속 기록으로 평가한다.
