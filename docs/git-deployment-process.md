# Git 이력과 EC2 배포 정리

> 이 문서는 2026-09-16의 정리 및 수동 배포 방식을 보존한 기록이다. 이후 작업 규칙과 승인된 이미지 자동 배포 설계는 [작업 및 배포 규약](development-and-deployment.md)을 따른다. 아래 소스 전송·EC2 빌드 절차는 새 표준이 아니며, 자동 배포 구현 완료를 의미하지 않는다.

2026-09-16에 로컬 주요 실행 파일과 EC2 `/home/ubuntu/stock-auto-trader`의 SHA-256을 대조해 일치를 확인했다. 대상은 range 실행기·전략·피드·원장·테스트, 기존 paper-cycle, KIS 클라이언트, 번들 빌드 스크립트, Compose 및 Dockerfile이다.

이전까지 로컬 작업 파일을 전송해 배포했으므로 과거 배포본에 커밋 SHA가 기록돼 있지 않았다. 이 문서는 과거 배포를 커밋 기반 배포였다고 소급해서 주장하지 않는다.

## 변경 보존

- 기존 로컬 커밋 2개(배포 구조 문서, EC2 paper 실행기)는 원격 main보다 앞서 있었으며 이번 PR에 포함한다.
- `bce4248`: 이미 배포된 실행기, 취소 판정·복구 및 시세 복구를 현재 상태 그대로 기록한다. 기존 미커밋 paper-cycle 진단 및 KIS 주문가격 변경도 삭제하지 않고 보존한다. 이는 모든 변경을 이번에 새로 작성했다는 뜻이 아니다.
- `42346f4`: README 변경, 전략 조사·전략안·실제 배포 기록을 보존한다. 채택하지 않은 전략 문서도 삭제하지 않는다.
- 후속 커밋에서 CI Node 22 정합성과 배포 커밋 추적을 추가한다. 실행 중인 전략의 매수·매도 조건을 이 작업에서 바꾸지 않는다.

비밀 환경변수·키·토큰·DB·백업은 커밋하지 않는다. 실제 계좌 수수료 확인 여부, 관찰·취소 검증 기록 등 문서의 당시 상태는 역사적 기록으로 읽어야 한다.

## 당시 수동 배포 절차 (역사적 기록)

1. 작업 브랜치에서 변경을 커밋하고 PR을 생성한다.
2. 테스트·린트·Next 빌드·paper 번들 빌드가 통과한 PR을 main에 머지한다.
3. 머지된 커밋을 `git archive <전체 SHA>`로 내보낸다. 작업 디렉터리의 미커밋 파일을 배포 묶음에 포함하지 않는다.
4. EC2의 별도 릴리스 디렉터리에 풀고 `docker build --build-arg GIT_COMMIT=<전체 SHA> -f Dockerfile.paper -t stock-auto-trader-range:<전체 SHA> .`로 빌드한다. 검증 후 운영 local 태그를 해당 이미지에 연결한다.
5. 기존 이미지와 원장을 백업한다. 현재 모의 보유·미체결을 대조하고 실행기를 정상 종료한다. 종료 후 다시 원장이 flat인지 확인한다. 불확실한 상태는 강제로 지우거나 원장 백업으로 덮어쓰지 않는다.
6. 서버 전용 환경설정과 데이터 볼륨을 유지한 채 해당 릴리스로 서비스를 시작한다.
7. `/health`, `/report.json`, 조회 화면, `runner_started` 이벤트 및 Docker OCI revision 라벨이 머지 SHA와 일치하는지 확인한다. 최신 시세·계좌 대조도 확인한다.

Dockerfile 기본값 `unknown`은 로컬 개발용이다. 운영 배포에서는 전체 머지 SHA를 반드시 전달한다. Git SHA는 소스 식별자이며 환경설정·외부 의존성·DB까지 같은 상태임을 뜻하지 않는다. 재현과 롤백을 위해 이미지 ID도 배포 기록에 남긴다.

CI는 EC2 런타임과 같이 Node 22에서 검증한다. SQLite 네이티브 모듈 때문에 기존 Node 20 설정은 사용하지 않는다.
