# 지정가 자동매매 추가 작업 계획

작성: 2026-10-07. 상태: 후속 구현 진행 중.
근거: PR #9 머지 SHA `6d2fd5d`, 로컬 구현 `881ec36`, 기존 상세 계획 `2428ac9:docs/strategy/manual-price-trading-plan-20261007.md`.
이 문서는 후속 구현의 기준과 완료 증거를 기록한다.

## 1. 목표와 기존 계획 변경

- KIS 모의투자, KODEX 코스닥150(229200), 배정 원금 100만원을 유지한다.
- 매수·매도 지정가와 예산은 사용자가 변경하기 전까지 보존한다. 기존 24시간 설정 만료를 제거한다.
- 적용 1회 후 한 회차만 거래하던 계획을 변경한다. 전량 매도 및 미체결 없음 확인 후 같은 설정으로 다음 회차를 대기한다.
- 설정의 영속성과 주문 실행 허가는 별개다. 월 평가 종료·손실 한도·중지·연결 장애로 실행이 중지돼도 설정값은 지우지 않는다.
- 최초 실제 매수 체결 시 한 달 평가를 시작한다. 서울 시각 기준 다음 달 같은 날짜·시각까지이며 해당 날짜가 없으면 말일로 정한다. 시작·종료·원금은 DB에 한 번 기록하고 설정 변경이나 재시작으로 초기화하지 않는다.
- 전략 순자산이 초기 원금보다 10만원 이상 감소하면 신규 진입 중지와 청산 절차로 전환한다. 체결 지연·급락·장외에는 손실 10% 이내를 보장하지 않는다.
- DB는 설정, 거래 손익, 주문 복구에 필요한 최소 기록만 보관한다. 초 단위 호가·정상 점검 로그는 저장하지 않는다.

## 3. 시세 수신과 주문 시점

아래 수치는 초기 운영 명세다. 증권사 제한을 확인하고 인수 검증에서 타당성을 확인한다. 제한과 충돌하면 코드만 바꾸지 않고 이 문서의 값을 함께 개정한다.

| 동작 | 기준 |
|---|---|
| 시세 | 실행기 한 개가 KIS 실시간 최우선 매수·매도호가 구독 |
| 매수 판단 | 정상 호가 이벤트마다 판단; 현재가가 아닌 최우선 매도호가가 지정 매수가 이하 |
| 생존 점검 | 메모리에서 1초마다 연결 상태와 마지막 정상 호가 시각 확인 |
| 호가 만료 | 수신 후 3초 초과 시 신규 매수 차단; 제출 직전에도 검사 |
| 시장 시각 검사 | 당일 거래일·종목·정상 가격, 시장 시각 지연 3초 초과 및 미래 1초 초과 데이터 차단; 시간 동기화 이상도 차단 |
| 연결 복구 | 구독 승인과 새 정상 호가 확인 후 계좌·미체결 대조를 마쳐야 신규 매수 재개 |
| 재연결 간격 | 1·2·5·10·30초 증가, 최대 30초와 작은 무작위 지연 |
| 설정 확인 | 장중 5초마다 버전 조회; 주문 의도 저장 트랜잭션에서 최신 버전 재확인 |
| 체결 대조 | 모의 환경의 체결 통보 지원 여부 확인 후 사용; 미확정 주문은 REST 대조 주기 목표 2초 |

실시간 미지원·구독 실패 시 오래된 현재가 조회로 자동 대체하지 않는다. 구현 전 KIS 공식 문서에서 모의 WebSocket 지원, 체결 통보, REST 호출 한도, 거래일 및 주문 조회 범위를 확인하고 문서 경로·확인일·테스트 결과를 남긴다. REST는 계좌 단위 요청 큐로 제한하고, 취소·기존 주문 대조를 신규 매수 조회보다 우선한다. 2초는 요청을 무제한 병렬 발행하라는 뜻이 아니다.

매수 조건 충족 시 사용자 지정가를 상한으로 매수 주문한다. 수신·검증·주문 의도 기록·증권사 접수 시각을 해당 주문에 기록해 지연을 측정한다. 특정 밀리초 안에 체결된다고 보장하지 않는다.

매도는 목표가까지 기다렸다 제출하지 않는다. 실제 매수 수량을 확정한 다음 사용자 지정가를 하한으로 매도 주문하고 체결을 기다린다. 더 유리한 체결가는 허용한다.

## 4. 회차·부분 체결·반복 규칙

`설정 대기 → 매수 조건 대기 → 매수 제출/확인 → 매수 체결·잔량 취소 확인 → 매도 제출/확인 → 전량 매도 확인 → 다음 회차 대기`

- 계좌당 동시에 진행하는 회차는 하나이며 회차의 설정 버전은 고정한다.
- 매수 주문이 전량 체결되면 즉시 매도 준비. 일부 체결이면 잔여 매수를 취소하고 최종 체결·취소 수량을 대조한 뒤 확정 수량만 매도한다.
- 전량 미체결 매수는 접수 후 5분에 취소한다. 취소 확인 후 30초 대기하고 새 정상 호가로 재판단한다. 최초 주문의 잔량이 불명확하면 재진입하지 않는다.
- 전량 매도 후에는 보유·미체결 0을 확인하고 최소 5초 후 새 호가로 다음 회차를 판단한다. 같은 호가 이벤트를 재사용하지 않는다.
- 매도 부분 체결은 이미 접수된 잔량을 추적하며 같은 수량을 추가 매도하지 않는다.
- 잔고·매수가능액이 부족하면 수량을 임의 축소하지 않고 사유와 함께 보류한다. 같은 설정의 계획 수량을 유지한다. 실현이익을 반영해 예산을 자동 확대하지 않는다.
- 명확한 거절은 이유를 표시하고 중지한다. 응답 유실은 `unknown`으로 저장하고 내역 대조 전 재전송하지 않는다.

## 5. 설정 유지와 화면

- 페이지 최초 진입 시 인증된 GET으로 DB의 마지막 저장값·실행기 수락값·상태를 조회한다. 조회 실패를 기본값이나 설정 없음으로 바꾸지 않는다.
- 상단에 저장된 매수·매도가, 예산, 변경 시각을 항상 표시한다. 실행기 수락 버전이 다르면 두 값을 구분한다.
- 입력란은 최초 조회값으로 채운다. 이후 조회가 사용자의 편집 초안을 덮지 않는다. 편집하면 `미적용 변경` 표시.
- 적용 클릭 시 API가 최신 비용표로 재검증하고 원자적으로 저장한다. 실패하면 기존 설정 유지. 미리보기는 DB에 저장하지 않는다.
- 같은 입력의 중복 적용은 새 회차·새 버전을 만들지 않는다. 응답 유실 후 재시도는 같은 요청 식별자를 사용한다.
- 주문·보유·미확인 주문·미완료 회차가 있으면 가격 및 예산 변경은 거절한다. 실행기가 오프라인이면 새 값 저장은 가능하나 실행기 대조 전 `저장됨·실행 확인 대기`다.
- 변경 저장과 이전 설정의 주문 의도 생성은 같은 계좌 잠금으로 직렬화한다. 새 버전 저장 후 이전 버전으로 신규 주문 금지.
- 화면 열림·탭 활성 상태에서만 5초마다 상태 조회. 숨겨진 탭은 주기 조회 중단, 복귀 시 즉시 조회. 가격 조건 판단은 브라우저가 수행하지 않는다.
- `신규 매수 중지`는 기존 매수 잔량 취소와 보유분 매도 관리를 계속한다. 버튼 성공과 실제 실행기 중지 확인을 구분한다. 재개도 별도 요청으로 기록한다.

## 6. 최소 DB 기록과 손익

별도 호가 이력·미리보기·일반 이벤트 테이블은 만들지 않는다. 다음은 필요한 최소 논리 데이터이며 일부는 동일 테이블에 합칠 수 있다.

| 데이터 | 저장 내용 | 목적 |
|---|---|---|
| 설정 버전 | 소유자, 내부 계좌 참조, 지정가·예산·수량, 비용 근거, 변경 시각·요청키 | 마지막 값 복원, 거래 기준 추적 |
| 계좌 제어 1행 | 저장/실행 버전, 중지 상태, 평가 시작/종료·원금, 실행권·마지막 생존 시각·사유 | 중복 실행 방지, 한도 유지 |
| 회차 | 설정 참조, 진행 상태, 시작/종료, 마지막 오류 사유 | 반복 거래 경계와 복구 |
| 주문 | 회차·매수/매도·지정가·수량, 제출 전 식별자, 증권사 번호·주문일, 상태·누적 체결, 취소 의도 | 중복 주문 및 과매도 방지 |
| 체결 | 중복 방지 키, 실제 가격·수량·금액·시간, 수수료·세금과 확정 여부 | 거래 순이익 계산 |

수수료가 주문 단위로 부과되면 주문에 원본 비용을 저장하고 체결 배분 합계가 일치하게 한다. 누적 체결만 제공되면 증가분을 원자적으로 반영해 재조회 시 중복 집계하지 않는다.

완료 회차 순이익 = 매도 체결금액 합계 − 매수 체결금액 합계 − 양쪽 수수료 − 세금.
미매도분은 실현이익에 넣지 않고 별도 평가손익으로 표시한다. 실제 비용 미확정이면 `추정 순이익`으로 표시한다. 월 평가에는 운영비를 별도 합계로 반영하며 비용 미입력은 비용 0원으로 확정하지 않는다.

요율은 정수 배율/고정소수점으로, 금액은 정수 원으로 계산한다. 합격 기준은 반올림 표시 전 비용 후 이익 > 0. 비용표 변경 시 설정은 보존하되 신규 매수 전에 재검증하며, 수량이나 비용 조건 변경은 재적용을 요구한다.

## 7. 운영비와 데이터 사용량

- 매초 점검은 메모리 연산이다. 매초 DB 쓰기·외부 REST 요청·정상 로그를 만들지 않는다.
- heartbeat는 거래 감시 중 15초마다 동일 계좌 제어 행 갱신. 화면은 45초 초과 시 실행 상태 확인 불가 표시. 행이 누적되지 않아도 쓰기 비용은 발생하므로 측정한다.
- 장외 대기 시 설정 조회·heartbeat는 60초 간격, 화면은 장외임을 별도 표시한다. 연결 생존만으로 주문 가능 상태라 판단하지 않는다.
- 예시로 6.5시간 가동하면 5초 설정 조회는 약 4,680회, 15초 heartbeat는 약 1,560회다. 거래 기록과 열린 화면의 조회는 별도다. 이는 청구액 추정이 아닌 사용량 예산이다.
- 정상 로그는 상태 변경에 한정하고 반복 오류는 합쳐 기록한다. 주문 관련 기록 외 진단 로그는 크기·보존 기간을 제한한다.
- 실행 인스턴스 종류·가동 시간·DB 요청량·로그량을 검증 보고서에 기록한다. 시간표만으로 보유 관리 중 서버를 자동 종료하지 않는다.

## 8. 거래 시간·중단·복구

- 초기 운영 범위는 KRX 정규장 연속매매로 한정한다. 날짜별 거래 일정에서 연속매매 시작/종료를 확인하고, 시작 후 5분부터 종료 10분 전까지 신규 매수를 허용한다. 고정 시각만으로 휴일·특별 거래일을 판단하지 않는다. 일정 미확인은 신규 매수 차단.
- 진입 종료 시 미체결 매수 취소·대조. 목표 미도달 보유는 유지하며 설정도 보존한다. 장 종료 후 주문 효력은 추정하지 않고 다음 거래일 실제 잔량을 확인한 뒤 필요할 때만 매도 재접수한다.
- 평가 종료/손실 한도 도달은 목표 매도가보다 우선한다. 신규 진입 중지 → 매수·기존 매도 취소 대조 → 확정 보유 청산. 장외에는 청산 대기, 주문 가능한 첫 세션에서 처리한다. 청산은 지정 매도가 아래의 손실 체결 가능성을 화면에 명시한다.
- 웹 중지는 신규 진입 중지다. 브라우저 종료와 실행기 종료는 다르며, 실행기 종료로 증권사 주문이 취소됐다고 표시하지 않는다.
- DB 장애 시 신규 주문 의도 기록이 불가능하므로 신규 매수·매도·취소 제출을 중지하고 장애를 알린다. 기존 주문은 남아 있을 수 있다. 복구 후 증권사 대조를 먼저 한다. 이 경우 자동 매도/손실 대응이 지연될 수 있음을 상태로 표시한다.
- 시세만 끊기면 신규 매수는 차단하되 DB·증권사 조회가 정상인 기존 주문의 체결 대조와 확정 보유의 지정가 매도 관리는 지속한다.
- 재시작은 최근 미완료 주문의 전체 조회 기간·페이지를 대조한 뒤 진행한다. 판단 불가능한 주문은 확인 필요 상태로 유지한다.
- 실행권 만료만으로 새 프로세스에 자동 주문권을 넘기지 않는다. 이전 실행기의 중단과 증권사 대조를 확인한다. 기존 range 실행기와의 중복 가동도 차단한다.

## 9. 접근 통제와 기존 데이터 이행

구현 첫 단계에서 기존 주문 진입을 차단하고 DB 접근을 보완한다. 현재 공개 정책을 유지한 채 기능만 확장하지 않는다.

1. 허용 사용자 로그인·계좌 소유권 검증, 읽기/쓰기 API 인증, 쿠키 요청의 출처 검증을 추가한다.
2. 전용 비공개 스키마 및 웹/실행기 DB 역할로 거래 자료 접근을 제한한다. 공개 키로 거래 기록을 직접 조회/변경할 수 없게 한다.
3. 이미 실행한 001 SQL을 덮어쓰지 않고 후속 마이그레이션으로 권한·스키마를 변경한다. 백업 및 테스트 DB에서 이행 검증을 선행한다.
4. 기존 설정의 소유자·계좌를 운영자가 확인해 연결하고 계좌 원문은 내부 식별자로 교체한다. 불명확한 데이터는 자동 활성화하지 않는다.
5. 마지막 사용자 설정은 보존하되 `재확인 필요`로 표시한다. 사용자 재적용과 증권사 보유·미체결 대조 후 새 실행기가 수락한다. 이 초기 이행 이후 정상 재시작에는 매번 재적용을 요구하지 않는다.
6. 이행 전 active 표시는 주문 증거가 아니다. 과거 실행기의 주문 결과가 로그뿐일 수 있으므로 증권사와 대조한다.
7. 앞선 작업 중 DB 비밀번호가 도구 출력에 노출된 이력이 있으므로 운영 연결 비밀번호를 교체하고 실제 사용하는 환경에 반영한다. 값은 출력하지 않는다.

## 10. 작업 순서와 완료 증거

| 순서 | 작업 | 완료 증거 |
|---|---|---|
| 1 | 최신 main·기존 실행 상태 확인, 주문 진입/공개 접근 통제 | 비로그인·타 사용자 접근 거절, 기존 주문 상태 확인 |
| 2 | KIS 공식 계약 확인, 최소 스키마·이행·정수 비용 계산 | 호출 제한/체결 키/일정 근거, 이행·권한·비용 경계 테스트 |
| 3 | 인증 API·원자적 적용·설정 복원 화면 | 다른 탭/재접속/재배포 후 값 유지, 충돌·중복 클릭 테스트 |
| 4 | 주문 상태·영속 원장·단일 실행·복구 | 부분 체결·취소 경합·응답 유실·재시작 테스트 |
| 5 | 실시간 호가·자동 매도·반복 회차·장/손실 제한 | 가상 시계와 가짜 브로커로 전체 회차·두 번째 회차 검증 |

| 7 | 수정 PR, CI, 이행 및 배포 | 테스트·lint·웹/실행기 빌드, 필수 CI, 실제 적용 SHA/digest |

최초 장중 인수는 동일 엔진을 작은 별도 인수 예산으로 검증하고 운영 기본값 100만원은 유지한다. 시장이 목표가에 도달하지 않으면 미체결로 기록하며 체결 검증 완료라 보고하지 않는다.

필수 테스트: 3초 경계·오래된/역순/다른 날 호가, DB 장애, 웹 종료, 프로세스 종료, 중복 실행, 중복 적용, 매수 일부 체결과 취소 중 추가 체결, 매도 일부 체결, 비용 확정, 장 종료/익일 재개, 평가 종료/손실 중단, 반복 회차의 예산·기간 불변.

## 11. 배포 및 완료 보고

- 한 개의 추가 수정 PR에 문서·마이그레이션·코드·테스트를 포함한다. 기존 PR #9가 완성됐다고 소급해서 표시하지 않는다.
- Vercel 웹과 지속 실행 워커 배포를 각각 검증한다. EC2를 사용하면 Compose/systemd가 실제 새 실행기를 시작하는지와 과거 실행기 중지를 확인한다.
- main→CI→ECR→EC2 규약을 따른다. EC2 오프라인은 적용 대기다. 워크플로 성공만으로 배포 완료라 하지 않는다.
- 필수 검사: `npm test`, `npm run lint`, `npm run build`, `npm run build:paper`, DB 통합·UI·복구 테스트.
- 보고는 계획 완료 / 구현·자동 검사 완료 / DB·웹·실행기 반영 / KIS 장중 왕복 검증을 구분한다. 최종 완료에는 자동 매도 및 체결·손익 대조 증거가 필요하다.

## 12. 이 문서 작성 시점 상태

후속 브랜치에서 002 마이그레이션, 설정 복원, 상태 머신, 매수 체결 후 자동 매도 실행기와 실행 비활성 기본값을 구현했다. 002 마이그레이션은 개발 Supabase에 적용하고 기존 설정 1건을 보존하는 것을 확인했다. KIS 장중 왕복 체결·EC2 신규 이미지 적용·접근 통제 인수는 아직 완료 증거가 없으며, 이 항목을 충족하기 전에는 전체 자동매매 완료로 보고하지 않는다.

## 2026-10-08 복구 보완 (검증 진행 중)

- 계좌의 blocked/needs_reconciliation 회차도 미완료로 취급한다. 가격 변경과 새 회차 생성으로 중지를 우회하지 않는다.
- 주문 제출 시각의 한국 날짜부터 오늘까지 조회하고 주문일·번호·종목·방향·요청 수량을 함께 대조한다. 자동 익일 재주문은 아직 구현하지 않았으며 불명확한 주문은 대조 대기로 유지한다.
- 003 마이그레이션에 주문별 누적 체결량·평균가·체결금액·추정 수수료 및 회차 추정 손익을 추가한다. 개별 체결 시각을 제공받지 않은 상태에서 가상의 개별 체결 행을 생성하지 않는다. 수수료는 확정이 아니며 운영비도 차감되지 않은 추정값이다.
- 매수 전량 미체결 취소 후 자동 재시도 대신 blocked 상태로 유지한다. 취소 응답 유실 또는 취소 대기 중 추가 취소를 반복하지 않는다.
- 호스트 서비스는 사용자가 masked 상태로 전환했다. 이 상태에서 기존 range용 자동 배포 성공을 기대하거나 서비스 차단을 해제해서는 안 된다. 지정가 배포/단일 실행/계좌 대조는 별도 구현·인수가 남아 있다.
- WebSocket, 접근 통제, 월 평가·손실 제한 등 원 계획의 미완료 항목은 이 수정으로 완료되지 않는다. 실서버 거래 활성화 전 잔여 항목 검증이 필요하다.
- 브로커 주문 가격에서 주식 호가표로 ETF 지정가를 내림하던 처리를 제거한다. 유효한 정수 지정가는 그대로 전달하고 비정상 입력은 거절한다. 예: 15,365원 매도 주문은 15,360원으로 변경하지 않는다.
