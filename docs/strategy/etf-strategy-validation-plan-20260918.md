# ETF 전략 선정·검증 작업 계획서

작성일: 2026-09-18 · 상태: 진행 중, 국내 ETF 성과 판정 보류

## 1. 목표와 이번 승인 범위

사용자는 보유시간이나 거래 빈도보다 수익을 낼 근거를 우선한다. 국내 ETF를 대상으로 공개 연구의 근거와 실제 데이터 검증을 함께 살펴보고, 비용 차감 후 성과와 위험이 사전 기준을 충족하는 전략만 KIS 모의투자 후보로 선정한다. 특정 수익률, 월 10% 또는 매일 거래를 채택 조건으로 삼지 않는다.

사용자 지시로 조사와 비교 기반 구현을 시작했다. 계획서와 구현·검증 결과는 **하나의 PR**로 제출한다. 별도 계획서 PR은 만들지 않는다. 커밋은 검토 가능한 단위로 나눌 수 있다.

이 문서는 향후 전략 선정 작업의 우선 기준이다. 과거 문서의 ‘사용자는 스캘핑을 원한다’는 방향은 이번 합의로 대체한다. 운영 중인 range 전략의 규칙이나 종료일은 이 계획만으로 변경하지 않는다.

## 3. 작업 단계와 산출물

### 1단계 — 연구 근거와 후보 규칙 고정

- 논문 원문, 저자 자료, 거래소·운용사·증권사 공식 자료를 확인한다. 공개 연구의 시장·기간·비용·레버리지·공매도 전제를 기록한다.
- 서로 독립적인 재현인지, 같은 백테스트의 재인용인지 구분한다. 해외 다자산 연구를 국내 단일 ETF 수익 증거로 바꾸지 않는다.
- 후보는 최대 3개로 제한한다. ① 단일 ETF 이동평균 추세추종 ② 절대 모멘텀 ③ 상대 모멘텀에 현금 대기 조건을 결합한 방식이다. 상대 모멘텀은 적절한 ETF 구성과 이력이 확보될 때만 포함한다.
- 기본 추세 후보는 120거래일선·주간 판단·진입 후 추가 비중 조정 없는 보유형을 시작 가설로 검토한다. 나머지 후보의 관측 기간·교체 주기·동률 처리·현금 조건도 성과 조회 전에 명시한다.
- 소수의 인접 파라미터는 민감도 확인용으로 사전 등록한다. 시험한 모든 조합을 기록하고 최종 평가 후 유리한 값으로 교체하지 않는다.

산출물: 출처·한계가 포함된 근거표, 후보 사양, 탐색 목록, 실행 전 고정한 평가 설정. 근거가 부족한 후보는 제외 사유를 남긴다.

### 2단계 — 데이터와 비용 모델 보완

- 비레버리지 국내 주식형 지수 ETF를 대상으로 충분한 상장 이력·유동성·사용 가능한 데이터에 따라 종목을 고정한다. 현재 인기 종목을 과거에도 선택 가능했던 것처럼 취급하지 않는다.
- 가능하면 5년 이상이며 상승·하락·횡보가 포함된 기간을 확보한다. 짧은 이력이나 현재 생존 종목만 사용한 한계를 기록한다.
- 원시 OHLCV, 수정 가격·수정계수, 분배금·분할, 거래일 달력을 확인한다. 신호용 가격과 실제 수량·현금 원장용 가격을 분리한다.
- 수정 가격에 반영된 분배금을 현금에 이중 반영하지 않으며, 분배락·지급일·분할 사례를 손계산과 대조한다. 제공 데이터의 수정 방식이 불명확하면 총수익 검증을 완료 처리하지 않는다.
- 수수료와 상품별 과세를 공식 자료 및 가능한 계좌 근거로 확인한다. 개인 요율을 확인할 수 없으면 출처 있는 가정과 민감도로 표시한다. 수수료 0을 확정값으로 사용하지 않는다.
- API 지연은 요청 종류별 지연·타임아웃·호출량으로 분리한다. 느린 증권사 응답인지 호출 구조 문제인지 확인한 뒤 필요한 수정 범위를 결정한다.

산출물: 데이터 품질 보고서, 출처·수집일·해시·기간을 가진 데이터 명세, 비용 설정, 미해결 제약 목록. 원본 데이터는 이용 권한에 맞춰 관리하고 거래 DB·키·계좌정보를 커밋하지 않는다.

### 3단계 — 재현 가능한 비교 검증 구현

- 기존 `daily.ts`를 확장하고, 별도의 중복 백테스트 엔진을 새로 만들지 않는다.
- 진입 후 보유와 정기 목표 비중 복원을 구분한다. 목표 비중 반환 때문에 의도하지 않은 매일 매매가 발생하지 않는지 검증한다.
- 확정 데이터로 신호를 만들고 다음 거래 가능 시점에 체결한다. 일봉 시가 체결은 실제 09:05 또는 10:30 지정가 체결의 근사임을 보고한다.
- 후보별 동일 원금·공통 평가 기간·비용·노출 기준을 적용한다. 다종목 후보는 현금 공유·정수 수량·교체 순서·미체결 예약을 반영한다.
- 현금, 동일 ETF 단순 보유, 노출을 맞춘 단순 보유를 비교군으로 둔다. 현금 이자는 확인된 값 또는 명시적 0 가정으로 통일한다.
- 일별 자산, 월별 손익, 실제 체결가와 비용, 미실현 손익, 최대 낙폭과 미회복 여부, 평균 노출·회전율을 재현 가능한 JSON/CSV 및 설명 보고서로 출력한다.
- 기존 낙폭·회복 기간 등 지표 구현도 독립적인 손계산 사례로 확인한다. 기말 강제 매각 유무와 청산 비용을 명시한다.

산출물: 비교 실행 명령, 고정 설정, 의미 있는 회귀 테스트, 재현 가능한 보고서 생성 경로.

### 4단계 — 기간 분리 평가와 채택 판단

- 시간순 개발 60% / 선택 20% / 최종 평가 20%를 기본으로 하되 실제 날짜를 결과 조회 전에 고정한다. 지표 준비용 과거 데이터는 허용하고 미래 정보는 사용하지 않는다.
- 워크포워드는 개발·선택 영역에서 수행한다. 최종 구간은 후보·설정을 고른 뒤 한 번 평가하고, 결과를 보고 수정하면 해당 구간의 미사용 지위를 해제한다.
- 기본 비용과 수수료·슬리피지 2배를 비교한다. 법정 세율은 해당 시점 값을 유지한다. 갭·결측·거래정지·체결 지연도 별도로 다룬다.
- 기간별·연도별 손익, 연환산 수익률, 최대 낙폭, 회복 기간, 최악 월, 손실 월 비율, 거래 수, 노출, 비용을 함께 보고한다. 짧은 기간을 연환산한 값은 한계를 명시한다.
- 사전 채택 문턱: 최종 구간 비용 후 총수익 양수, 비용 스트레스에서도 양수, 비교군 대비 수익 또는 위험상의 이점, 여러 구간에서의 재현성. 저빈도 전략은 거래당 평균만으로 판정하지 않는다.
- 최대 낙폭 8%를 기존 문서에서 이어받은 **잠정 연구 문턱**으로 사용한다. 이는 실전 손실 동의나 보장값이 아니다. 노출 기준과 함께 평가 전에 고정하며, 결과가 나쁘다는 이유로 사후 완화하지 않는다.
- 특정 시기 한 번의 이익에 의존하거나 거래·시장 국면이 부족하면 `판단 보류`로 남긴다. 전부 실패하면 ‘채택 후보 없음’이 정상적인 완료 결과다.

산출물: 후보 전체 결과표, 채택·기각·보류 근거, 데이터·설정·코드 버전, 불확실성과 재현 명령을 포함한 최종 연구 보고서.

### 5단계 — 통과 후보의 모의 실행 준비

이 단계의 구현은 4단계 통과 후보가 있을 때만 진행한다. 실패하면 억지로 전략을 주문 경로에 연결하지 않는다.

- 백테스트와 모의 실행이 같은 확정 데이터·전략 함수·일정 규칙을 사용하도록 연결한다. 주문 실행과 전략 신호는 구분한다.
- `TRADING_MODE=paper`, `ALLOW_LIVE_TRADING=false`를 유지한다. 초기 주문은 1주이며 연구용 100만 원 성과와 구분한다. 기존 운영 노출 한도를 자동 확대하지 않는다.
- 날짜를 넘기는 보유, 휴장, 예약 실행 누락, 서버 꺼짐, 재부팅, 부분체결, 응답 유실, 중복 방지, 위험 중지와 기존 포지션 관리의 동작을 정의하고 검사한다.
- 기존 range 원장과 새 전략 성과를 구분하면서 실제 계좌 소유권은 한 실행기에만 둔다. 이전 포지션·미체결이 남으면 자동 전환하지 않는다.
- 장기 보유 전략에서는 기존 배포 규약의 flat 조건 때문에 교체가 오래 보류될 수 있다. 강제 청산이나 안전 조건 완화 없이 대기 상태를 표시하고 운영 절차에 기록한다.
- 배포 관련 수정 시 `.github/workflows/`, `Dockerfile.paper`, `deploy/image/compose.yaml`, systemd와 제어기를 검토한다. 신규 기능은 명시적 활성화 전 주문하지 않는 기본값으로 준비한다.

산출물: 모의 실행 어댑터·설정·운영 문서·주문 없는 검증 결과. 서버 적용 및 장기간 관찰은 PR 개발 완료와 별도로 기록한다.

## 5. PR 이후 운영 검증과 중단 조건

머지·이미지 발행·EC2 적용·주문 활성화는 다른 단계다. 이 계획서 작성은 어느 단계도 승인하거나 실행하지 않는다. 후속 지시 범위에 따라 진행하고 실제 digest·Git SHA·서버 보고서로 적용을 확인한다.

모의 운영은 주문·체결·잔고·비용 대조가 목적이며, 저빈도 전략의 짧은 흑자를 수익성 입증으로 취급하지 않는다. 기존 문서의 8~12주는 관찰 시작 구간으로 참고하되 표본 부족은 그대로 남긴다. 거래 횟수를 채우기 위한 강제 주문은 하지 않는다.

데이터 이용 불가, 과세·분배금 처리 불명확, 최종 평가 실패, 반복 계좌 대조 실패나 미확인 주문이 있으면 해당 단계에서 보류한다. 데이터 확보가 막혀도 독립적인 검증 코드·명세 작업은 계속하고, 필요한 사용자 입력을 구체적으로 보고한다. 실전 전환은 별도의 명시적 지시가 필요하다.

## 6. 현재 진행 결과와 남은 작업

1단계의 공개 근거 검토와 비교용 절대 모멘텀·매수 후 보유 구현을 완료했다. 연구 출처와 KIS 데이터 수집 실패는 [근거·데이터 결과](./etf-strategy-evidence-20260918.md)에 기록한다. 합성 시계열 테스트는 구현 성질만 검증하며 실제 성과 증거로 쓰지 않는다.

실제 일봉·분배금 데이터가 확보되기 전에는 2~4단계의 전략 성과 판단을 끝내지 않는다. 후보가 사전 문턱을 통과하지 않았으므로 5단계 모의 주문 경로는 진행하지 않는다. 사용자 요청 범위는 하나의 PR로 완성하되, 이 데이터 한계와 보류 결론을 PR에서 명확하게 표시한다.
