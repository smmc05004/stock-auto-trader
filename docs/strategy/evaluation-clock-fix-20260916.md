# 조회 지연에 따른 잘못된 준비 대기 수정

작성일: 2026-09-16. 대상: KIS 모의투자 kr-etf-range-v0.2. 전략 가격·수량·위험 한도와 10초 공백 기준은 변경하지 않는다.

## 확인한 문제

`tick()` 시작 시각을 계좌 대조 이후에도 사용했다. 주문·잔고 REST 조회를 기다리는 동안 WebSocket 수집기는 최신 수신 시각을 기준으로 30분 버퍼를 정리한다. 조회가 약 20초 지연되면, 과거 평가 시각과 최신 버퍼를 조합해 관찰 구간이 29분 50초 미만이라고 판단한다. 실제 연속 데이터가 있어도 `warming_30m`이 반복될 수 있었다. 보고서는 현재 시각으로 재계산해 실제 판단과 다른 사유를 표시했다.

## 변경

1. 계좌 대조 완료 후 평가 시각과 한국 날짜·시간을 갱신한다. 신규 진입·자동 취소 검증·시세 신선도·분당 평가·구간 산출에 같은 시각을 사용한다. 매수 직전의 최신 시세·15:15 차단도 유지한다. 조회 후 급변을 다시 확인하고, 주문 취소 기한과 박스 종료 시각은 실제 처리 시각으로 계산한다.
2. `state.lastDecision`에 실제 판단 시각·사유·당시 데이터 품질을 저장하고 `decision` 이벤트에 동일 내용을 남긴다. `entry_selected`는 구간 선택이며 체결 성공을 뜻하지 않는다. 주문·체결은 기존 원장 이벤트로 확인한다.
3. 보고서의 `lastDecision`과 `entryBlockReason`은 마지막 실제 판단이다. `currentEntryStatus`와 `marketData`는 현재 상태의 미리보기다. 진행 중 계좌 조회·이후 시세 변화 때문에 서로 달라질 수 있다. 기존 DB에 판단 기록이 없으면 `null`/`not_evaluated`로 표시한다. 과거 판단을 최신 판단처럼 만들어 내지 않는다.
4. `broker_request`에 TR, 큐 대기·인증 및 속도 제한 준비·HTTP 처리·총 소요 시간, HTTP 상태, 제한된 오류 코드, 성공/오류/타임아웃을 기록한다. API 키·토큰·계좌번호·응답 본문·임의 오류 메시지는 기록하지 않는다. 요청 단위이므로 페이지 조회는 여러 이벤트로 표시된다. 자동 재주문·취소 재시도는 추가하지 않는다.
5. `feed_ready`로 구독 복구 시각·연결 소요·연결 중단부터의 시간을 기록한다. 호가 수집 공백 자체는 `quote_gap`으로 구분한다. 오래된/미래/잘못된 제공 시각 때문에 폐기한 프레임은 프로세스 누적 카운터로 보고하고, `feed_frame_dropped`는 첫 건과 이후 최대 분당 1회 기록한다. 카운터는 재시작하면 초기화되며 이벤트는 DB에 남는다. 마지막 이벤트 이후의 카운터까지 장애 시 영속화되는 것은 아니다.

공백 해제 시각은 추가 공백이 없을 때의 보수적인 예상이며, 해제 후에도 전략 조건이 충족되지 않으면 주문하지 않는다.

## 검증 및 배포

- 가짜 시계와 모의 브로커로 조회 도중 20초 연속 수집을 재현: 수정 전 시각은 warming, 완료 시각은 정상 구간 선택·주문.
- 실제 공백, 오래된 시세, 15:15 진입 마감, 15:00 사전 검증 마감, 일일 위험 제한과 분당 평가 유지.
- SQLite 판단 이벤트·저장 상태·보고서의 실제 판단 일치 및 현재 미리보기 구분.
- 오류·타임아웃 계측, 민감 데이터 제외, 시세 폐기 계수 및 기록 빈도, 재연결 시각 검증.
- 브랜치 → 검사 → PR → 필수 CI → main 머지 → 이미지 배포 절차를 따른다. 이번 PR 생성은 머지·EC2 적용 완료가 아니다. 최초 이미지 운영 전환과 자동 배포 활성화가 아직 필요하다.
- 배포 후 `gitCommit`, `revision=evaluation-clock-20260916`, 실제 판단 시각, `broker_request`, `quote_gap`을 대조한다. 최신 데이터가 충분한 구간에서 조회 지연만으로 warming이 반복되지 않는지 확인한다. 실제 체결은 별도로 확인하며 수익성 개선을 보장하지 않는다.
